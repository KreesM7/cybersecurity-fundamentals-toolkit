# Delivery verification

Verified locally on 2026-10-06 with Windows 11 x64 (build 26200), Python 3.12.14, and the exact direct dependency versions in `requirements.txt`.

- Complete unittest suite: **50 tests passed**, including the real libmagic renamed-PNG test when configured with matching x64 MSYS2 UCRT64 file 5.48 DLL/database and dependencies. Native components were downloaded into scratch storage and checked against the package publisher's SHA256 values; they are not part of the source deliverable.
- Independent reviewer: approved the expanded public-target safeguards after checking bounded DNS, IP pinning, retained request protections, and stale UI results. The independent full run passed 48 tests with one native libmagic skip; after the final stale-result fix, all nine GUI tests passed independently, including already-queued discovery/probe results followed by A→B→A URL edits. Earlier hardening covered slow HTTP/chunk framing, repetitive-response comparison, and protocol cardinality.
- Controlled fixtures verified public literal and hostname acceptance, pinned DNS, original Host headers, DNS deadlines/cancellation, unsupported DNS-answer rejection, GET discovery/probes, POST blocked without explicit permission, enabled POST, the request budget, redirect blocking, cross-origin exclusions, oversized responses, slow headers/body/chunked-response cancellation, and rejection of an untrusted HTTPS certificate. Public-address transport was redirected to the loopback fixture. No real public targets or LAN devices were scanned.
- Scanner verification used controlled process output and the actual python-nmap XML parser, plus interface/target guards. **Real Nmap execution and routing remain unverified here because the external executable is not installed.** Home provides the setup message.
- Qt checks covered navigation through all seven panels, custom scanner routing and permission, target edits clearing permission/forms and cancelling old work, stale discovery/probe result rejection, dependency failure isolation, worker results on the main thread, event-loop responsiveness, cancellation, shutdown, password masking/Clear, module discovery, and resources from a different working directory.
- Saved-file checks covered threshold boundaries, out-of-order CSV and access logs, malformed rows, valid and truncated PCAP/PCAPNG, short baselines, explicit zero variance, bounded protocol labels, and bounded retained results. Synthetic examples were checked against their documented expected results.
- `pip check` reported no broken requirements.
- The project's own `.venv` was created with the available Codex Python 3.12.14 runtime and populated from `requirements.txt`. `Start-Toolkit.cmd --self-test` passed from a different directory, and the normal source launch opened the native toolkit window. This also verifies setup without a Python runtime registered with the Windows launcher.
- PyInstaller 6.22.3 produced a windowed one-folder local build. Its `--self-test` exited **0** from a different directory after the recipe isolated native DLL discovery from unrelated PATH entries. The spec collected all seven modules and bundled resources/examples. The test build stays in scratch storage; no executable distribution is delivered.
